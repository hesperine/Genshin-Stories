# 原神剧情编年 · 阅读器

双击 `index.html` 就能阅读当前已编译的剧情文档。网页本身不依赖服务器；正文与目录由 `story-data.js` 提供，文中引用的远程 CG 图片需要联网。白天／夜晚主题、字号、行宽、侧边栏状态和阅读进度保存在当前浏览器的 `localStorage`。通过侧栏可导出或导入阅读记录。

## 普通版与史诗版

正文上方可切换两种讲述方式，切换后仍停留在同一节。当前 1.0—7.1 的 53 个版本、88 页均提供史诗稿，翻页会保留当前讲述方式。序章入口为 `index.html#v=1.0&s=0&e=epic`，7.1 入口为 `index.html#v=7.1&s=0&e=epic`。未来新增的普通版页面若尚无对应史诗稿，会禁用史诗按钮；从史诗版翻到这类页面时，会显示普通版并提示切换。

两版的已读页与上次阅读位置分别保存，字号、主题和行宽共用。导出的 JSON 同时包含两版记录；旧 JSON 可继续导入，原有已读页归入普通版。原有 `#v=版本&s=序号` 链接仍指向普通版。

史诗稿放在 `../story-editions/epic/`，每页一份 Markdown，文件名使用已有页面标识，例如 `v1.0-s0.md` 或 `v3.0-sintro.md`。一级标题须与普通版页题相同，正文直接写在其下，可用三级标题分节；末尾的 `## 资料` 单独进入来源区域。构建脚本会检查页面对应关系，拒绝标题错位、空稿和拆成多页的改写。普通版继续保存在原目录，页序与标识沿用已有安排；两版正文已同步复核，详见[逻辑复核记录](../docs/epic-logic-review.md)和[首次阅读视角的衔接修订](../docs/first-reader-followup.md)。无新增魔神任务的版本按实际收录事件命名，任务分类仍保存在原文件名和构建数据的 `chapter` 字段中。

## 后续加入版本

1. 在 `../story-summaries/N.x/` 放入 `N.M-章节号-章节名.md`，例如 `7.1-第七章第三幕-示例.md`。没有主线时使用 `N.M-无.md` 或 `N.M-无-支线名.md`。
2. 正文首行用 `# 版本号｜标题`，每个「幕」或重要世界支线用 `##` 标题；`###` 可在同一页内划分小节。首个二级标题前的正文会以文章标题单独成页；短引言请放在对应的二级标题下。末尾的 `## 资料` 会成为最后一页的可展开来源。
3. 在项目根目录执行：

   ```powershell
   python -m pip install markdown-it-py==3.0.0
   python reader/build.py
   ```

构建脚本自动扫描所有 `N.x` 文件夹，按版本号数值排序，生成 `story-data.js`。编号页使用 `v版本-s序号` 标识，独立的篇首正文使用 `v版本-sintro`，单独分出篇首正文不会改变已有编号页的标识。保持版本号与幕顺序不变，旧链接、已读记录和导出的记录便可继续使用。只有一页的文章直接显示文章标题。直接打开 `reader/index.html` 检查结果。

每页显示按正文每分钟约 400 字估算的阅读时长，最低为 1 分钟；插图、资料链接与停留思考的时间另计。

修改构建逻辑后，可运行 `python -m unittest discover -s reader -p "test_*.py"` 检查分页、标题、阅读标识和史诗稿对应关系。运行 `node --test reader/test_state.cjs` 检查旧记录导入、两版进度、链接和导出后的恢复。

## 部署到 GitHub Pages

将整个项目上传到 GitHub 仓库。在仓库 **Settings → Pages → Build and deployment** 中把 Source 设为 **GitHub Actions**。推送到 `main` 或 `master` 分支，或在 Actions 页手动运行 **Deploy reader to GitHub Pages**。工作流会在 GitHub 上重新生成数据并发布网页；发布地址见 Actions 部署结果或 Pages 设置页。

GitHub Pages 上的阅读进度只存储于访问者自己的浏览器。跨设备阅读可使用侧栏的导出／导入记录。

## 操作

- 点击页面下方按钮、按键盘 `←`／`→` 或在手机上横向轻扫翻页。
- 左上角按钮收起或打开目录；手机上点击空白遮罩可关闭目录。
- 未读版本与未读幕在侧栏显示占位标题，进入该页后才揭示。
- 来源链接在每篇版本的最后一页底部展开。
